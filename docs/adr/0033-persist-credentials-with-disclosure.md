# Persist credentials with disclosure rather than refusing

Cyd persists account-control credentials through one desktop-wide credential store, which keeps them outside every account database, media directory, and Cyd archive, and encrypts each value with the operating system's facility wherever one is available. Where none is, on a Linux desktop with no keyring, behind a password store Cyd does not recognize, or on a platform that offers nothing, Cyd stores the credential in the clear in the same owner-only vault and tells the user so, in a warning bar that names the password store and in the startup log, rather than refusing to persist it. Refusing was implemented first and was worse: Electron reports encryption as unavailable whenever Chromium falls back to `basic_text`, which is exactly the keyring-less case, so refusal made the Bluesky migration unusable there and destroyed working sessions on upgrade. Credentials Cyd already holds in plaintext are moved into the store when an account database opens, whether or not the operating system can protect them, because the vault is owner-only and outside the archives, exports, and error reports the config table was not. Cyd revokes before it discards wherever it holds a usable credential, so disconnecting or deleting an account invalidates the session at the authorization server rather than merely forgetting it locally.
