# Refuse unprotected credential storage

Cyd persists account-control credentials through one desktop-wide credential store, which encrypts each value with the operating system's facility and keeps it outside every account database, media directory, and Cyd archive. When that facility cannot protect a credential, Cyd refuses to persist it rather than falling back to application-managed plaintext: the user reconnects instead. Chromium's `basic_text` password store on Linux is the single deliberate exception, allowed only because a Linux desktop without a keyring is common, and only when the fallback is detected and disclosed in the app; a password store Cyd does not recognize gets no such exception. Credentials Cyd already holds in plaintext are moved into the store when an account database opens, and destroyed along with the account's claim to be connected when they cannot be protected, because an unprotected credential is worse than none. Cyd revokes before it discards wherever it still holds a usable credential, so disconnecting or deleting an account invalidates the session at the authorization server rather than merely forgetting it locally.
